### fix

- **device-gateway**: forward `POST /api/device/agent/run` body verbatim to the device via spread semantics, matching upstream `...runParams`. All optional fields (`args`, `imageList`, `assistantMessageId`, `ingestWorkspaceId`, `resumeFallbackSystemContext`, `workspaceId`, etc.) and future client-added fields now reach the device; empty arrays/objects are preserved instead of dropped.
- **agent-gateway**: implement `wantStatus` opt-in and `resume_complete` handshake in `handleResume`, aligning with upstream LOBE-10443. Fixes lobehub 2.2.13 "stuck in resume buffer, messages not rendered" — the client sends `{type:'resume', wantStatus:true}` and expects a `resume_complete` reply to exit resume mode; the gateway previously never sent it.
- **agent-gateway**: only emit `resume_complete` when a real `SessionStatus` is stored; status missing (init/resume race) stays silent so the opt-in client keeps waiting instead of false-completing.
- **agent-gateway**: `newOperation` no longer pre-sets `StatusRunning`; status starts empty and is set by `/api/operations/init`, mirroring upstream DO storage lifecycle.
- **agent-gateway**: append `?includeCount=0` when calling LobeHub `/api/v1/users/me` for apiKey auth, aligning with upstream `5dd2ff7` "perf: use lightweight current user lookup". Avoids triggering the heavyweight user query on every auth.
