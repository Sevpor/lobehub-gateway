# 0.4.0

## Added

- Agent Gateway protocol v2 at `GET /v2/ws`: one authenticated WebSocket per browser tab can subscribe to multiple operations.
- Per-operation subscribe, unsubscribe, replay, numeric sequence deduplication, gap reporting, pending-init handling, and executor-aware `tool_execute` routing.
- User-level `op_lifecycle` feed with operation status and the supported `init.meta` fields.
- V2 forwarding for `tool_result`, `tool_confirmation`, `user_input`, and compatibility no-op `interrupt` messages, with subscription ownership checks.

## Compatibility

- The v1 `GET /ws?operationId=...` protocol remains available. Authentication completed before `init` is now rechecked when the operation owner becomes known.
- Resume replay uses numeric event ids when the requested id has fallen out of the buffer and reports `gap` to status-aware clients.
- `tool-execute` and `update-status` refresh operation activity, and tool-result forwarding includes `executionTimeMs`, `state`, and `workRegistration`.
- Per-operation v2 delivery is serialized by event id, and v1 authentication atomically rechecks ownership when racing with `init`.
- V2 delivery queues are bounded; failed or persistently backpressured subscriptions are disconnected so clients can recover through normal reconnect and replay.
- Retried operation initialization without `meta` preserves metadata already associated with the operation.
- Device-side `tool_execute` dispatches use the 30-minute in-flight watchdog window.
- The Agent Gateway alignment target is `aeaf0abc63134974f803eebf4c1851c5e8f7bf37`.

## Runtime constraints

- V2 hub connections and subscriptions use the existing single-process in-memory design. They are not coordinated between gateway replicas and are lost on restart.
